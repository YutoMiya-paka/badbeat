# テスト計画（バッドビート相談所）

公開前・変更時に何を確かめるかの一覧。Claude と GPT（Codex）が独立に洗い出した観点を統合したもの（2026-09-29）。
各項目の末尾の記号は出どころ: **[両]** 両者が挙げた／**[C]** Claude だけ／**[G]** GPT だけ。

## 分類と優先度の見方
- 方法: **Node** = `node` で自動 ／ **画面自動** = ブラウザで自動（仕組みは「画面テストの自動化」を参照） ／ **実機** = スマホ実機で手動
- 優先度: **毎回** = 公開前の最小セット ／ **変更時** = その機能を触ったとき・大きな変更のとき ／ **定期** = たまに（月1程度）

## 公開前の最小セット（毎回・約10分）
1. `node tools/test-engine.js` と `node tools/test-apps-script.js` が全部通る。
2. 画面（手元サーバー、スマホ幅 375px）で次を 1 回ずつ:
   - `AhKh vs QsQd フロップでオールイン Qc 8h 3h 2s 9d`（2♠ を含む入力・フロップ判定）
   - `AA vs KK`（プリフロ判定・特別セリフ）
   - `今日はありがとう`（「今日」入りのあいさつがお礼の返事になる）
   - `KKで3回負けた` → `4回`（1 日まとめの聞き返し → 結果）
   - 口調を切り替えて再読み込み → 口調が残っている
3. ライト／ダーク両方で、判定カードの見出しが見える位置にスクロールされ、「くわしく見る」が開閉できる。
4. スマホ幅で、入力欄タップ → カード欄が閉じて「カードで選ぶ」帯が出る／「カード」でカード欄が開く。送信ボタンが押せる。
5. 公開後、GitHub Pages と Netlify の両方で: 版数（APP_VERSION）が新しい、見本の判定が出る、送信ボタンに何も被っていない、コンソールにエラーが無い。
6. 記録まわりを変えたときだけ: テスト用の受け口（または手元の `POST /log`）で 1 件の送信内容を確認。本番シートには試験データを入れない。

## 画面テストの自動化（決めること）
Claude と GPT で推奨が分かれた。

| 案 | 中身 | 良い点 | 弱い点 | 推した側 |
|---|---|---|---|---|
| A. 依存なしのテストページ | `tools/ui-test.html` を手元サーバーで開くと、本物の index.html を同じ場所の枠（iframe）に読み込み、入力・クリック・表示を順に確かめて結果を一覧にする。記録の送信は偽物に差し替える | 追加のインストール無し。**スマホ実機のブラウザでもそのまま開ける**。本物のページを動かすので中身がずれない | 画面幅・ダークの切り替えは枠の大きさや設定で工夫が要る。コマンド 1 つで回す形（CI）にはしにくい | Claude |
| B. Playwright を入れる | `npm` で開発用に導入。手元サーバーを立ててブラウザを自動操作 | 画面幅・ダーク・通信の確認が簡単。コマンドで回せる | 導入（ブラウザのダウンロード約数百 MB）と更新の手間。実機のキーボードは再現できない | GPT |
| C. Node だけで HTML を模擬実行 | DOM を自作の偽物で動かす | 依存なし | CSS・レイアウト・フォーカスが確かめられない | 両者とも非推奨 |

- **両者一致**: 画面ロジックをテスト用に複製しない（本物のページを動かす）。記録の送り先はテスト中は必ず偽物にして本番シートに書かない。実機のキーボードはどの方法でも再現できないので実機確認は残る。
- **Claude の推奨**: まず A で「最小セット」と回帰テストを自動化し、足りなくなったら B を足す。
- **GPT の推奨**: 最初から B。

## Node テストで次に足すもの（依存なしですぐできる）
1. 記録の payload が Apps Script の `valid_` を通るか（ページ側の組み立てを関数に切り出す必要あり）
2. 勝率の不変条件（合計 1・組み合わせ数・入れ替え）、フロップ／ターンの既知値、リバーの救う札、勝ち・引き分けの検出
3. 役判定の総当たり突き合わせ（乱数 1 万手）
4. やさしめの文言に荒い言葉が無い／engine のエラー文すべてにやさしめの言い換えがある
5. 受け口の doPost を偽物のサービスで丸ごと通す
